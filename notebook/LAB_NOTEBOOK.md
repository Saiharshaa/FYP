**Failed / not done**

  The dev machine is Windows with no Docker and no WSL. The tests are written

  Added a guard that refuses to run off-POSIX.

**Findings that affect the method**
- The canonical-solution check is partly circular. evalplus computes the
  expected outputs by running the canonical solutions (`get_groundtruth`),
  so 164/164 validates the pipeline, not canonical correctness. The labels
  mean "agrees with the canonical solution on the base+plus inputs". The
  report should state this as a label-quality limitation.
- Timeouts are host-dependent. The per-test limit is max(1 s, 4 × the
  canonical runtime measured on the current host). Timeout labels (an H3
  category) can therefore flip between machines or under load. Label the
  corpus on one fixed host and record it.
- The subprocess backend's network isolation depends on the host. It uses an
  unprivileged network namespace (`unshare --net`) if permitted; otherwise it
  falls back to a Python socket guard, which can be bypassed and is not a
  security boundary.
